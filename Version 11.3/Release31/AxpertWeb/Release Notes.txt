3. Cookie with Insecure or Improper or Missing SameSite attribute
 Note: The following web.config file node should be enabled based on the customer's site configuration and integration requirements.
  a. HTTPS without SSO and without external iframe calls to AxpertWeb: 
    Web.Config node: <httpCookies httpOnlyCookies="true" requireSSL="true" sameSite="Strict"/>
     a1. Enables HttpOnly and Secure cookie protection.
     a2. SameSite=Strict provides stronger protection against cookies being sent in cross-site contexts.
     a3. Recommended where SSO and cross-site iframe scenarios are not required.
   b. HTTPS with SSO and/or external iframe calls to AxpertWeb:
     Web.Config node: <httpCookies httpOnlyCookies="true" requireSSL="true" />
     b1. HttpOnly and Secure remain enabled.
     b2. SameSite=Strict is not enabled by default because it may affect SSO redirects or cross-site iframe scenarios.
     b3. The appropriate SameSite policy should be determined based on the customer's SSO/integration architecture and validated through the applicable SSO and iframe flows.
   c. For HTTP deployments where cross-site access is not required:
    Web.Config node: <httpCookies httpOnlyCookies="true" sameSite="Strict"/>
     c1. HttpOnly protects the cookie from client-side JavaScript access.
     c2. SameSite=Strict restricts the cookie to same-site contexts.
     c3. HTTPS is strongly recommended for production, because HTTP does not provide encrypted transport and the cookie cannot have the Secure protection while being used over HTTP.

5. Cross-Site Request Forgery 
  Note on this security point: The reported CSRF condition was reviewed. The signin.aspx page uses an _antiforgery token, which is validated against a server-side session token. When the _antiforgery parameter is removed or modified, anti-forgery validation fails and the request is not processed. The additional parameters reported by AppScan are optional/application-flow-specific parameters and are not required in all login scenarios. Therefore, their removal does not indicate successful CSRF execution.
 Action Required: No additional configuration or code changes are required for this security point.

6. Cross-Site Request Forgery 
  Note on this security point: The reported parameter hdnbtforLogin is an application-specific login parameter and is not the CSRF security control. The signin.aspx page implements server-side anti-forgery token validation using the _antiforgery parameter. The token is validated against the server-side session token before processing the request. The additional parameters removed by the scanner are flow-specific and are not mandatory for every request. Therefore, their removal or manipulation does not by itself indicate a successful CSRF attack.
  Action Required: No additional configuration or code changes are required for this security point.
