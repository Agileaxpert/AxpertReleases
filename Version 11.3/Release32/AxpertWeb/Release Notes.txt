TKT-0735 – GCMS – RCSAT Security Audit Report:
1. Using Known Vulnerable Components:
  a. Moment.js: Version removed 
  b. Lodash : Version removed 
  c. Handlebars: Handlebars was identified as version 4.7.9. The security advisories reviewed list versions up to and including 4.7.8 as affected, with 4.7.9 identified as the patched version. Therefore, no vulnerability was identified for the deployed Handlebars version based on the advisories reviewed. Since 4.7.9 is a secure/patched version, it should continue to be used.
Version disclosure note: The Handlebars version is intentionally retained because version 4.7.9 is the patched version. Removing the version information would only hide the version from tools such as Wappalyzer/Retire.js and would not provide any security benefit.


2. CSV Injection:
   a. Input characters: Characters such as =, +, -, @, and tab can be valid data and therefore should not be prohibited globally. The CSV Injection risk occurs when an exported value is interpreted as a formula by spreadsheet applications. Formula-leading values should therefore be neutralized during CSV generation/export.
   b. Form-level validation: For the affected form(s), an AxBeforeBlur hook in custom.js can validate user input for values that may be interpreted as spreadsheet formulas and display a warning or restrict the entry as required.
If such values are restricted at the data-entry level, they will not be saved to the database through that form and consequently will not appear in reports generated from the stored data.

Implementation / Reference: 
For reference, the custom.js file has also been provided. Please add it to the application and identify the forms that require this validation.
custom.js is common to all forms. If the validation is required only for a particular form or specific forms, the validation can instead be implemented in the corresponding form-specific JavaScript file, using the form's transid as the filename (for example, transid.js).

6. Cookie with Insecure or Improper or Missing SameSite Attribute:
   a. The below web.config setting was released as part of Release31. However, it appears that the setting is still commented out and therefore is not enabled. Hence, the same issue may still occur.
   web.config:
   <!-- HTTPS without SSO and without external iframe calls to AxpertWeb -->
   <!--<httpCookies httpOnlyCookies="true" requireSSL="true" sameSite="Strict"/>-->

   b. Based on the application URL provided in the security report, the customer environment appears to be running over HTTP rather than HTTPS. Therefore, enabling requireSSL="true" is not suitable for the current customer environment, as it would require the application to be accessed over HTTPS.
   For the current HTTP deployment, the below setting has been added to web.config. This configuration enables HttpOnly and SameSite=Strict for cookies without requiring SSL, allowing the application to continue operating over HTTP.
   web.config:
   <!-- HTTP without SSO and without external iframe calls to AxpertWeb -->
   <httpCookies httpOnlyCookies="true" sameSite="Strict"/>

   c. For environments where AxpertWeb is deployed over HTTPS, the HTTPS-specific configuration should be enabled instead:
   web.config:
   <!-- HTTPS without SSO and without external iframe calls to AxpertWeb -->
   <httpCookies httpOnlyCookies="true" requireSSL="true" sameSite="Strict"/>

   d. The appropriate configuration should be enabled based on the customer's deployment environment:
   HTTP environment: httpOnlyCookies="true" sameSite="Strict"
   HTTPS environment: httpOnlyCookies="true" requireSSL="true" sameSite="Strict"
